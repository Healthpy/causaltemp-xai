# results/

Output of the numbered experiment-phase scripts in `experiments/`. Everything
here is regenerated by re-running the phases — nothing under `results/` is a
source-of-truth artifact.

```
results/<config>/axis_b_benchmark.json   Axis B: graph diagnostic, once per dataset (Phase 01)

results/<config>/<classifier>/
    cf/X_sel.npy                 factual instances selected for explanation
    cf/X_cf_<Method>.npy         one array per CF method   (Phase 03)
    attribution.json             IG deletion/insertion-AUC foil               (Phase 03)
    axis_a_attribution.json      Axis A: causal-relevance of IG saliency
                                  + Axis D input-sensitivity                  (Phase 03)
    shift_vr.json                Axis D: CF-method validity retention         (Phase 03)
    eval_<Method>.json           Axis-C (+ TRSI/IVR) + CF-faith per method    (Phase 04)
    per_instance.csv             one row per (method, instance)              (Phase 04)
    summary.json                 combined: methods + axis_a + axis_b + attribution + shift_vr

results/<config>/oracle/         nonlinear configs (smoke_nl / full_nl)       (Phase 05)
    eval_<Name>.json
    per_instance.csv
    summary.json

results/tables/
    table_axis_c_cf_faith.csv    accumulated, one row per (benchmark, classifier, method) run

results/figures/
    fig1_validity_vs_cffaith.png
    fig2_cffaith_distribution.png
    fig3_rank_correlation.png
```

## Axis routing

The benchmark's four metric axes (`causaltemp_xai/metrics/axis_{a,b,c,d}.py`)
are each evaluated on the kind of method they are actually suited to —
see the `experiments/_common.py` module docstring for the full rationale:

| Axis | What it measures | Evaluated on | Where |
|---|---|---|---|
| **C** | validity, proximity, sparsity, OOD, TRSI, IVR | every selected CF method (CARLA, CftsWachter, CftsCOMTE, CftsConfeti, CftsCounts, CftsCels, OracleCF-\*) | Phase 04 (linear) / 05 (nonlinear) |
| **CF-faith** | does the CF respect the known SCM mechanisms (rollout / pearl) | same as Axis C | Phase 04 / 05 |
| **D** (Shift-VR) | validity retention under a noise-distribution shift | every selected CF method | Phase 03 |
| **D** (input-sensitivity) | stability of a saliency map under small input perturbations | attribution methods (IG) | Phase 03 |
| **A** | ICC / causal-coverage of a saliency map, scored against ground-truth oracle interventions | attribution methods (IG) | Phase 03 |
| **B** | SHD / LagAcc / TV-Confounding of the SCM's own causal graph | the dataset itself (no graph-discovery method is wired in, so this is a structural diagnostic, not a per-method score) | Phase 01 |

Every axis that scores counterfactual explanations (Axis C + CF-faith, Axis
D's Shift-VR) runs over the **full** selected CF method set — no method is
singled out. The gradient-based Wachter baseline is the cfts-backed
`CftsWachterCF`; the native from-scratch `WachterCF` implementation is not
used in this pipeline.

## Pipeline

```bash
# 1. Generate benchmark datasets (writes to data/scm_t/, gitignored)
uv run python experiments/01_generate_benchmarks.py --config smoke
uv run python experiments/01_generate_benchmarks.py --all

# 2. Train the LSTM classifier (linear configs only)
uv run python experiments/02_train_classifiers.py --config smoke

# 3. Run CF methods + attribution + shift-VR, persist raw artifacts
uv run python experiments/03_run_cf_methods.py --config smoke --n-cf 20

# 4. Score persisted CFs (Axis-C + CF-faith), write eval JSON + tables
uv run python experiments/04_evaluate_axes.py --config smoke

# 5. NlinearSCM-T: oracle structural-CF positive control (no classifier needed)
uv run python experiments/05_run_oracle_nonlinear.py --config smoke_nl

# 6. Render figures from everything under results/
uv run python experiments/06_make_figures.py
```

See `docs/plans/mvp-v0.1-completion/` and `docs/plans/nlinearscm-t/` for the
design rationale behind each metric and the linear/nonlinear benchmark split.
